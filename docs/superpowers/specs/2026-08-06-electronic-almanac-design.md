# 电子黄历桌面应用设计

日期：2026-08-06  
状态：已确认  
目标版本：v0.1.0  
项目目录：`D:\APP\电子黄历`

## 1. 产品目标

制作一个面向 Windows 10/11 的轻量电子黄历桌面应用。应用随用户登录 Windows 静默启动并常驻系统托盘，用户点击托盘图标即可快速查看当天黄历卡片，也可以进入当日详情页查看完整信息。

首版追求三个结果：

1. 打开快：点击托盘图标后能立即看到当天摘要。
2. 常驻轻：不依赖网络、数据库或每日缓存，不持续做高频计算。
3. 信息清楚：用传统纸历视觉呈现实用黄历内容，但不制造神秘化或权威化暗示。

## 2. 已确认的产品决策

- 独立 Windows 桌面应用，不并入“每日计划与复盘”。
- 技术栈采用 Tauri 2、React、TypeScript 和 Rust。
- 发布为 NSIS 当前用户安装包，安装路径固定且默认不要求管理员权限。
- 首次启动询问是否启用开机自启动；设置中可以随时修改。
- 后续开机时静默启动，只显示系统托盘图标，不自动弹出窗口。
- 左键点击托盘图标显示极简黄历卡片；右键显示应用菜单。
- 视觉采用“传统纸历”：低对比纸张纹理、深褐文字、朱红日期。
- 首版只提供今日摘要和当日详情，不提供月历或历史日期查询。
- 黄历数据通过本地开源库计算，不使用需要 API Key 的在线接口。
- 对外保留薄的 `AlmanacProvider` 接口，但首版不实现在线 Provider。
- 不保存逐日黄历缓存；日期变化后直接重新计算当天数据。

## 3. 首版范围

### 3.1 托盘黄历卡片

卡片参考尺寸为 `360 × 500`，无系统边框，显示在用户点击的托盘图标上方。卡片包含：

- 公历日、月份和星期。
- 农历日期。
- 干支年与生肖。
- 当天节气或节日；没有内容时隐藏该行。
- 最多 3 项“宜”和最多 2 项“忌”。
- “查看详情”按钮。
- “本地计算 · 无缓存”的状态说明。

交互规则：

- 左键点击托盘图标切换卡片显示与隐藏。
- 卡片显示时按 `Esc`、点击卡片外部或再次点击托盘图标都会隐藏卡片。
- 卡片不出现在 Windows 任务栏中。
- 卡片只在显示期间置于其他普通窗口上方。

### 3.2 当日详情页

详情窗口参考尺寸为 `620 × 760`，使用正常桌面窗口行为，可最小化和关闭。详情内容包含：

- 公历、农历、星期。
- 年、月、日干支与生肖。
- 节气和节日。
- 完整宜忌。
- 冲煞。
- 时辰详情及吉凶或宜忌信息。
- 固定说明：“传统民俗信息仅供文化参考，请勿作为医疗、法律、财务或其他重要决定的依据。”

内容超出窗口时纵向滚动。关闭详情窗口只隐藏窗口，不结束后台进程。

### 3.3 托盘菜单和设置

右键托盘菜单包含：

- 查看今日黄历。
- 开机自启动开关。
- 关于。
- 彻底退出。

首次启动显示一次自启动询问。用户同意后调用系统自启动能力；用户拒绝后保持关闭。无论首次选择如何，之后都能从设置修改。

询问提供“开启”和“暂不开启”两个明确操作。直接关闭询问窗口等同于“暂不开启”，并记录为已经询问，避免每次启动重复打扰。

### 3.4 明确不做

- 月历网格和历史日期查询。
- 在线黄历接口、账号、云同步或远程配置。
- 每日提醒、通知推送或日程管理。
- 天气、新闻、星座运势或个性化算命。
- 用户生日、八字或位置数据。
- 每日黄历文件、SQLite 数据库或长期历史缓存。
- 自动更新和 Microsoft Store 发布。

## 4. 视觉与可用性

### 4.1 视觉方向

- 主背景使用温和米褐色，不使用高饱和金色或大面积鲜红。
- 日期使用朱红色和衬线数字字体，作为第一视觉层级。
- 正文使用深褐色，纸张纹理保持轻微，不能影响小字号清晰度。
- “宜”和“忌”同时显示文字标签，不能只靠绿色和红色区分。
- 详情页延续卡片风格，不增加新的视觉主题。

### 4.2 缩放与窗口边界

- 支持 Windows 100%、125%、150%、175% 和 200% 常见显示缩放。
- 卡片位置根据托盘点击事件和当前显示器工作区计算。
- 卡片必须限制在可见工作区内，兼容任务栏位于屏幕上、下、左、右的情况。
- 卡片固定尺寸；详情页在内容溢出时滚动，不通过无限增大窗口解决。

## 5. 技术架构

### 5.1 分层

1. **Tauri/Rust 壳层**
   - 应用生命周期。
   - 系统托盘及托盘菜单。
   - 小卡片和详情窗口创建、显示、隐藏、聚焦与定位。
   - 单实例处理。
   - 开机自启动。
   - 彻底退出。

2. **React 界面层**
   - `TrayCard`：托盘摘要卡片。
   - `DailyDetail`：当日详情页。
   - `FirstRunPrompt`：首次启动自启动询问。
   - `SettingsView`：自启动状态和关于信息。

3. **领域层**
   - `DailyAlmanac`：应用内部统一黄历模型。
   - `AlmanacProvider`：按日期获取黄历信息的接口。
   - `LocalAlmanacProvider`：调用 `lunar-javascript` 并转换字段。
   - `summaryRules`：从完整宜忌中生成卡片摘要。
   - `dateRules`：系统本地日期和跨午夜判断。

4. **设置层**
   - 只持久化必要设置，不保存黄历日数据。
   - 自启动实际状态以操作系统插件查询结果为准，不在设置文件中复制一份可能过期的状态。

### 5.2 窗口划分

- `tray-card`：启动时创建但隐藏；无边框、不进任务栏，负责快速摘要。
- `main`：启动时创建但隐藏；正常窗口，负责详情、首次询问和设置。
- 应用启动后始终保持后台事件循环，直到用户选择“彻底退出”。
- 单实例插件拦截后续启动；再次启动只显示或聚焦现有卡片。

两个窗口共享同一份当日领域数据，不各自重复计算。

### 5.3 数据模型

```ts
type ISODate = `${number}-${number}-${number}`;

type AlmanacHour = {
  label: string;
  range: string;
  level?: "auspicious" | "neutral" | "inauspicious";
  suitable: string[];
  avoid: string[];
};

type DailyAlmanac = {
  date: ISODate;
  weekday: string;
  lunarDate: string;
  ganzhiYear: string;
  ganzhiMonth: string;
  ganzhiDay: string;
  zodiac: string;
  solarTerm?: string;
  festivals: string[];
  suitable: string[];
  avoid: string[];
  clash?: string;
  sha?: string;
  hours: AlmanacHour[];
};

interface AlmanacProvider {
  getByDate(date: Date): Promise<DailyAlmanac>;
}
```

`DailyAlmanac` 只包含界面真正使用的字段。第三方库对象不能直接传给 React 组件，避免未来替换数据源时牵动整个界面。

## 6. 数据来源与刷新

首版使用 MIT 协议的 `lunar-javascript`：

- 仓库：<https://github.com/6tail/lunar-javascript>
- 用途：公历、农历、干支、生肖、节气、节日、宜忌、冲煞和时辰信息。
- 依赖只封装在 `LocalAlmanacProvider` 中。

首版以锁定版本的 `lunar-javascript` 输出作为应用口径。不同黄历流派或应用的宜忌结果可能不同，因此产品不承诺与其他黄历逐字一致，也不在界面中混合多个来源。

决策：`lunar-javascript` 1.7.7 在民用日边界拆分子时；v0.1 按源库顺序保留 13 个时段，不合并也不丢弃。

刷新流程：

1. 应用启动时读取系统本地日期。
2. Provider 计算当天完整黄历并保存到进程内存。
3. 卡片和详情窗口读取同一份内存状态。
4. 后台每分钟检查一次本地日期字符串。
5. 每次显示卡片或聚焦详情窗口时也检查日期，覆盖电脑睡眠后计时器被暂停的情况。
6. 只有日期变化时重新计算并替换内存状态。
7. 应用退出后内存状态自然释放，不写入黄历缓存文件。

如果未来新增在线 Provider，也必须由用户明确选择，并单独设计隐私、缓存、失败回退和接口密钥方案；首版不预留相关设置界面。

## 7. 摘要规则

- 保留 Provider 给出的宜忌顺序，不自行判断或重新评分。
- 卡片最多显示前 3 项“宜”和前 2 项“忌”。
- 某一列表为空时显示“未列出”，不虚构内容。
- 节气优先于普通节日显示；同一天两者都有时可并列一行。
- 冲煞只在卡片空间允许时显示一行摘要，完整内容始终放在详情页。
- 不生成 AI 提醒、吉凶分数或个性化建议。

## 8. 启动、托盘与退出流程

### 8.1 首次启动

1. 创建单实例锁。
2. 初始化托盘和两个隐藏窗口。
3. 计算当日黄历。
4. 如果尚未询问过自启动，则显示首次启动询问。
5. 用户选择后保存“已询问”标记，并根据选择调用自启动插件。
6. 询问关闭后保留托盘图标。

### 8.2 后续开机启动

1. 静默启动应用。
2. 创建托盘图标并计算当天黄历。
3. 不自动显示任何窗口。

### 8.3 关闭和退出

- 卡片失焦：隐藏卡片。
- 关闭详情：隐藏详情窗口。
- 托盘“彻底退出”：移除托盘图标并结束进程。
- Windows 注销或关机：允许系统正常结束进程，不执行缓存清理，因为没有黄历缓存。

## 9. 错误处理

### 9.1 黄历计算失败

- 保留应用可用状态，卡片仍显示公历日期和星期。
- 显示“黄历信息暂时无法生成”。
- 详情页显示可理解的错误状态，不显示堆栈或内部错误文本。
- 下次显示卡片或日期检查时允许重新尝试计算。

### 9.2 字段缺失

- 可选字段缺失时隐藏对应栏目。
- 宜或忌为空时显示“未列出”。
- 时辰数据不完整时只展示已成功转换的条目，不制造占位吉凶。

### 9.3 自启动失败

- 调用失败后重新查询系统状态。
- 开关恢复到真实状态。
- 显示“未能开启开机自启动，请稍后重试”的提示。
- 失败不影响托盘和黄历查看。

### 9.4 窗口与单实例

- 定位计算始终将窗口坐标限制在当前显示器可见区域。
- 如果无法取得托盘图标坐标，回退到当前显示器任务栏附近的安全位置。
- 第二实例不能创建第二个托盘图标，只唤起第一实例。

## 10. 隐私与本地数据

- 应用不联网，不收集使用数据，不上传日期或设备信息。
- 不请求位置、通讯录、日历或通知权限。
- 设置文件只保存“是否已询问自启动”等必要界面状态。
- 不保存每日黄历、用户行为或历史查看记录。
- 设置文件损坏时回退到默认设置，并重新询问必要选项。

## 11. 测试策略

### 11.1 自动测试

1. **Provider 适配测试**
   - 普通日期字段转换。
   - 春节日期。
   - 闰月日期。
   - 节气交界日期。
   - 宜忌、冲煞和时辰详情转换。

2. **纯领域规则测试**
   - 宜忌摘要数量和顺序。
   - 空列表显示规则。
   - 节气与节日组合。
   - 跨午夜日期变化，使用可注入时钟，不等待真实时间。

3. **窗口定位测试**
   - 四个任务栏方向。
   - 多显示器边界。
   - 常见缩放比例下的坐标限制。
   - 无托盘坐标时的回退位置。

4. **React 组件测试**
   - 卡片完整、部分和错误状态。
   - 详情页完整、部分和错误状态。
   - 首次启动询问。
   - 自启动开关成功和失败。

5. **Rust/Tauri 检查**
   - `cargo check`。
   - 单实例和窗口事件处理中的纯函数测试。

测试黄历库时只验证适配和代表性结果，不在应用中重复实现第三方库的完整历法算法。

### 11.2 Windows 手动 smoke

1. 安装 NSIS 当前用户安装包。
2. 首次启动只询问一次自启动。
3. 启用后重新登录 Windows，确认只出现一个托盘图标且不自动弹窗。
4. 左键显示卡片，再次点击、按 `Esc` 和点击外部均能隐藏。
5. 右键菜单各项可用，“彻底退出”后进程结束。
6. 详情窗口可打开、最小化、关闭和再次打开。
7. 断网状态下仍可显示完整黄历。
8. 检查应用数据目录，只存在小型设置文件，没有逐日缓存。
9. 卸载后应用文件和自启动注册均被移除。
10. 发布版启动时不出现命令行窗口。

## 12. 验收标准

- Windows 登录后应用静默启动，只有一个托盘图标。
- 左键点击托盘图标后 1 秒内显示可交互卡片。
- 卡片和详情页展示当天的实用黄历字段。
- 跨过午夜后无需重启即可切换到新日期。
- 断网不影响黄历计算和查看。
- 不产生逐日黄历缓存，长时间使用不会因历史缓存持续增长磁盘占用。
- 后台空闲时不进行高频计算，CPU 占用保持接近空闲状态。
- 界面不使用持续动画；空闲后台只保留不短于 60 秒的日期检查。
- 自启动失败、黄历计算失败和字段缺失都有明确且不崩溃的处理。
- 自动测试、前端构建、Rust 检查和 Windows 安装包 smoke 全部通过。
- 发布版无命令行窗口，可正常安装和卸载。
